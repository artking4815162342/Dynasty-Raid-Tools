# Dynastia Raid Tools (DRT)

## Область действия

Памятка относится только к каталогу аддона DRT. Пути ниже указаны относительно этого каталога. Не привязывать проект к расположению клиента или инструментам конкретной машины.

DRT предназначен для WoW Pandaria Classic. Версия: `2.0.0`; TOC Interface: `50504, 50503`. Порядок загрузки: `Notes.lua`, затем `Core.lua`. Сторонних библиотек для работы в игре не требуется.

## Структура

- `Notes.lua`: постоянное хранилище по GUID персонажа, миграция, владельцы, флаг шаринга, временный кэш чужих заметок, упаковка и проверка снимков.
- `Core.lua`: WoW API, события, редактор, миникарта, отдельное окно заметки, очередь сообщений, чат.
- `DRT.toc`: версия, метаданные, порядок загрузки, SavedVariables.
- `media/GuildCrest.tga`: прозрачная иконка гильдии.
- `tests/regression.lua`: тесты модели и настоящего кода аддона с имитацией WoW API, таймеров и нескольких клиентов.
- `tests/run.py`: запуск тестов на Lua 5.1 через Lupa.
- `README.md`: установка, поведение, миграция и проверки.
- `REVIEW.md`: результаты ревью, исправленные дефекты и ограничения проверки.

При установке папка называется `DRT` и находится в `Interface/AddOns` клиента. Путь текстуры `Interface\AddOns\DRT\media\GuildCrest.tga` в коде и TOC является игровым путём ресурса, его не сокращать до пути относительно репозитория.

## Поведение

Общей/главной заметки и переноса в неё больше нет. Все заметки имеют конкретного владельца.

- Игрок создаёт, редактирует и удаляет только свои заметки текущего персонажа.
- У своей заметки есть чекбокс «Шарить», по умолчанию включённый.
- Новая заметка до первого сохранения имеет `localOnly = true` и не отправляется.
- В группу/рейд отправляются только сохранённые заметки с `shared = true`.
- Переключение «Шарить» применяется сразу к сохранённой версии заметки. Несохранённый текст редактора не отправляется.
- Выключение шаринга и удаление обновляют список у остальных участников; локальная приватная заметка остаётся у владельца.
- Свои заметки расположены первыми в списке и помечены «моя», приватные дополнительно помечены «приватная». У чужих указан владелец; редактирование и удаление отключены.
- Полное имя владельца с сервером отображается в редакторе и подсказке. Совпадение коротких имён не означает совпадение владельцев.
- «Линкануть» вручную отправляет сохранённый текст выбранной заметки в текущий канал группы. Это отдельное действие, доступное и для приватной заметки.
- «Обернуть» добавляет строки из 25 символов `<` и `>`.
- Быстрая вставка: восемь рейдовых меток и игроки текущей группы/рейда; Shift+ЛКМ вставляет имя без завершающего пробела.

Синхронизации со всей гильдией нет.

## Владение и сохранность

SavedVariables: `DRTDB`. Клиент сохраняет её вне проекта при `/reload` или выходе из игры. Не редактировать пользовательские сохранения без явного запроса.

Основное правило: автоматическая очистка и входящие сообщения никогда не изменяют таблицы личных заметок.

- `DRTDB.characters[GUID].notes[id]`: постоянные личные заметки персонажа.
- `DRTDB.characters[GUID].owner`: актуальное полное имя владельца.
- `revision`: монотонная версия публикуемого снимка; `nextID`: счётчик ID; `windowKey`: заметка, выбранная для отдельного окна.
- `DRT.store.remote`: только временные расшаренные заметки текущих участников. Не записываются в SavedVariables.
- `DRT.store.revisions`: принятые версии снимков по отправителям.
- `DRT.store.drafts`: несохранённые изменения редактора в памяти текущей сессии.
- `DRTDB.noteWindow`: геометрия, включение и закрепление отдельного окна.
- `DRTDB.minimap.angle`, `DRTDB.wrapLinkedNote`: остальные настройки.

Поля своей заметки: `id`, `owner`, `ownerGUID`, `title`, `body`, `updated`, `shared`, временный признак `localOnly`. Принадлежность определяется расположением объекта в личном профиле, а не строкой owner из сообщения.

Ключ выбора личной заметки: `local:<id>`. Для чужой: полное имя владельца + `\030` + ID. Эти пространства ключей разделены.

GUID сохраняет владение при переименовании персонажа. Переход на другого персонажа переключает профиль, но не очищает предыдущий. До получения полного имени и GUID инициализация откладывается.

## Миграция с 1.0.0

Миграция выполняется в `DRTNotes.Open()`, версия схемы `2`.

1. Старая смешанная таблица `DRTDB.notes` копируется в `legacyNotes`. В старом формате нельзя надёжно отличить заметки другого своего персонажа от чужих, поэтому архив не чистится автоматически.
2. Записи, чей владелец совпадает с вошедшим персонажем, копируются в его профиль. `legacyClaims` отмечает импортированные записи, чтобы повторный вход не восстановил явно удалённую заметку.
3. При входе другим персонажем импортируются его записи. Неоднозначные и повреждённые старые записи остаются в архиве.
4. Непустой текст прежней общей заметки сохраняется как обычная приватная «Сохранённая заметка» у первого вошедшего персонажа. Старое поле `main` удаляется.
5. Геометрия прежнего окна переносится, показ выключается до выбора конкретной заметки.

Архив не участвует в списке и сетевой отправке. Не удалять его при «чистке чужих заметок». Если имя персонажа изменилось до первого запуска новой версии, автоматическое сопоставление старой записи может быть невозможно; архив позволяет восстановить её отдельно.

## Протокол и очередь

Префикс `DRT2`. Версии 1.x и 2.x не обмениваются заметками: участникам требуется обновление.

- `REQ`: запрос актуального снимка.
- `SNAP`: полное имя владельца, версия снимка, количество заметок, затем ID/updated/title/body для каждой расшаренной сохранённой заметки.
- Поля имеют длину в байтах и упаковываются `DRTNotes.Pack()`; `Unpack()` проверяет длины и границы.
- Данные кодируются percent-encoding и делятся на части по 170 байт: `C|id|index|total|part`.
- Допустим только текущий канал `INSTANCE_CHAT`, `RAID` или `PARTY`. Входящие сообщения от посторонних и из других каналов отбрасываются.
- Владелец снимка обязан совпадать с настоящим отправителем события WoW. Собственные входящие сообщения не применяются.
- Части собираются отдельно по отправителю и ID. Проверяются номера, размер, совпадение общего количества и повторных частей.
- Снимок целиком валидируется перед заменой кэша только этого отправителя.
- Устаревшие и повторные версии не применяются. Более новый снимок без заметки удаляет её из чужого кэша.
- Очередь отправляет одну часть раз в 0,35 секунды. Новый шаринг/сохранение/удаление отменяет старые неотправленные части.
- Изменение состава отменяет старую очередь и сборку частей, очищает только недоступные чужие заметки и запускает новый обмен.
- Запрос клиента после reload во время передачи вызывает повтор полного снимка после текущей передачи.
- Лимиты сетевого снимка: 512 заметок, 64 КиБ тела одной заметки, 320 байт названия, 512 КиБ закодированного снимка. Слишком большое сохранение расшаренной заметки отклоняется с сообщением, введённый текст остаётся в редакторе. Приватный текст не ограничивается сетевым лимитом.
- Большие снимки передаются дольше; отсутствие обновления до получения последней части не означает удаление локальных данных.

После reload чужой кэш сначала пуст и восстанавливается обменом. После выхода из группы он очищается. Личные заметки остаются в обоих случаях.

## Интерфейс

Основное окно `DRTMainFrame`: 920x620, слой `DIALOG`. Отдельное окно `DRTNoteWindow`: слой `HIGH`, по умолчанию 300x150, минимум 80x42. Основное окно находится выше отдельного.

Чекбокс «Показывать поверх UI» выбирает текущую личную или чужую заметку для маленького окна, без копирования. «Закрепить окно» отключает движение, изменение размера и перехват мыши. Подпись в углу: `DRT`. Удаление/отзыв доступа/выход владельца скрывает недоступную заметку.

В редакторе используется нативная каретка WoW EditBox. Не возвращать кастомную каретку, `ScrollingEdit_*` или принудительный `SetCursorPosition()` по клику. `RefreshRemoteUI()` не перезаполняет редактор своей заметки при входящих обновлениях. Черновики сохраняются при переключении заметок, но не переживают reload без нажатия «Сохранить».

Рейдовые метки отображаются текстурами в отдельном окне и чат-токенами при линковке. Разбиение длинных строк чата учитывает границы UTF-8.

## Команды и проверки

- `/drt` или `/дрт`: открыть/закрыть окно.
- `/drt sync`: запросить расшаренные заметки участников.
- Команда очистки общей заметки удалена.
- `/console scriptErrors 1` и `/reload`: проверка в клиенте.

Запуск из корня репозитория DRT:

```text
python -m pip install --target .test-deps lupa==2.8
python tests/run.py
git diff --check
```

`.test-deps` и `__pycache__` исключены из Git и не нужны в релизе. Используется именно `lupa.lua51`, чтобы не пропустить несовместимый с WoW синтаксис.

Тесты покрывают личные/приватные/чужие заметки, миграцию, альтов и переименование, отзыв доступа, задержанные сообщения, reload, 40 клиентов, подделку владельца, некорректные пакеты, черновики, отдельное окно и чат. Имитация API не подтверждает визуальный результат и доставку сообщений живым сервером: после изменений проверять в игре каретку, размеры, слои, шаринг между двумя клиентами и reload/выход из рейда.

При смене версии обновлять `VERSION` в `Core.lua` и `## Version` в `DRT.toc`. Сохранять русскоязычные файлы в UTF-8.
